# Actions公開・実セット較正の実行記録

2026-10-07。対象は `mizuki7minori-blip/magista` のmain。

## 公開した実行経路

`Draft calibration (real data and published reports)` をmainへ公開した。workflow_dispatchから対象セット、卓数、seed、実績の開始日/終了日、未確認プールの診断モードを指定できる。workflow自身のmain更新でも初回検証が動く。

既存 `update-limited-rankings.yml` の `20 2 * * *` は変更していない。日本時間11:20の1日1回更新を維持している。

外部取得はセット別に順次実行。timeoutは1セット30分、HTTP20秒、最大3回retry。途中ページ、前回成功データ、取得期間別cacheを保持する。ドラフトは読み込み後offlineで実行する。

生成物は14日保持のartifact `draft-calibration-{set}-{seed}` と、専用 `calibration-results` ブランチに残す。publish jobだけにcontents:writeを付与し、reports配下の限定JSON/CSVのみコミットする。push後にリモートHEADと照合する。失敗結果はerrors配下に残し、前回成功データを消さない。公開サイトのHTML/controllerは今回の公開対象に含めていない。

## 実取得で判明した問題

初回はScryfall全ページの取得に成功したが、取得カード全件が `booster:false` だった。既存のbooster判定で全件除外され、14枚パックを生成できなかった。公式封入対象と断定せず、通常の除外判定は維持した。

`--unverified-main-set-pool` は**診断専用**の明示的オプション。全セットカードをoracle単位で重複除去して試行するが、公式封入対象・Play Boosterを再現したとは扱わない。workflow入力 `unverified_pool=false` なら通常のbooster判定を使う。現時点ではfalseで全5セットの入力検証が止まる。

基本土地の専用枠、通常レアリティ枠、旧特殊枠の近似は以前の設定を維持。公式確率を新しく推測していない。カード別のrarity比率はシミュレーション結果であり実封入率ではない。特殊枠集計は旧対象プール所属での分類で、実印刷シートの出現率ではない。

## CPU判断の追跡

`{SET}-cards.csv` はカード別の取得順位、ATA/ALSA、GIH WR/OH WR、基本推定値、WR寄与、実ピック時の各補正平均、推奨理由の頻度を保存する。

`{SET}-pick-trace.json` は初回1卓・336判断に限定して、上位3候補の基本評価、全補正、理由、最終評価、±0.4のCPUブレを記録する。seed再現性を維持し、乱数を追加で消費しない。全100卓の全候補ログを無制限に保存しない。

`{SET}-summary.json` にはカード取得/重複/欠損、Scryfall ID照合率とjoin方法、WR収録率、色/色ペア、採点分布、23枚確保率、2色完結率、スプラッシュ率、土地枚数、色源供給の近似診断、Pearson/Spearman、異常フラグを保存する。

ATAは平均取得順位の定義が一致する場合だけ比較。ALSAは最終目撃順位なのでATAと同じ相関に混ぜない。公式封入とプールが未確認のためATA相関も診断値に限定する。GIH WRとOH WRの欠損は他指標で埋めない。色/アーキタイプ実績は取得できたraw wins/gamesを保存する。

## GitHub画面での実行

1. https://github.com/mizuki7minori-blip/magista/actions を開く。
2. **Draft calibration (real data and published reports)** → **Run workflow**。
3. branch=main、set_codes=`fra,hob,msh,sos,tmt`、tables=`100`、seed=`12345`。
4. start_date/end_dateは実際に比較する17Lands期間を入力する。今回の初回検証は2019-01-01〜2026-10-07の広い取得期間であり、セット発売日を確定した期間ではない。
5. `unverified_pool=true` は全セットカードによる非公式プール診断。公式封入確認後は対象カードを明示的に管理して再実行する。
6. Artifactsをダウンロードし、summaryのstatus、packEligibility、収録率、欠損とanomaliesを先に確認する。
7. https://github.com/mizuki7minori-blip/magista/tree/calibration-results/reports/draft-calibration で生成ファイルのコミットを確認する。

今回、CPU・採点係数は変更していない。実績のある3セット以上と、封入対象を確認したプールが揃うまで、相関だけを上げる変更は採用しない。

|---|---|---|---|
| WR信頼度 | min(games/1000,1) → 据え置き | 900/1000/1100の固定seed感度試験 | 実績未収録のfallback問題を重みで隠さない |
| ATA/ALSA評価重み | 0 → 0 | まず取得順位との乖離分析 | 市場順位と単体性能は同一ではなく、循環評価を避ける |

土地枚数は現在の40枚デッキ・17土地モデルによる値で、実ドラフトによる土地枚数最適化の測定ではない。色源供給は超幾何分布の近似で、実対戦のキャスト成功率ではない。
